# MISB ST 0601.19 requirement trace

This is a living trace for normative requirements implemented by the package.
Section references are to the official 2 March 2023 publication. `Partial`
marks a whole-standard claim whose remaining producer facts or nested-standard
semantics cannot yet be proven by the current executable evidence.
The trace explicitly accounts for all 33 active requirement identifiers in the
current corrected publication; retired Appendix A requirements are historical
and are not implementation targets.

The typed root registry covers every active Item 1 through 142; deprecated Item
66 is intentionally absent. Item 143 has a dedicated typed pack codec and is
accepted only inside Segment or Amend Local Sets, as required by ST 0601.19-45.

## Remaining ST 0601.8-14 closure scope

Every active root item now has a typed wire representation, exact length and
domain enforcement, and item-specific regression evidence. The broad
ST 0601.8-14 claim deliberately remains partial for these narrower reasons:

- producer facts not present in the KLV bytes—metadata time of birth, IMAP
  system precision, and whether reported values truthfully describe the sensor
  and image—are enforceable only when the caller supplies the corresponding
  validation context. `ST0601FieldExpectation` supports exact or
  tolerance-aware comparisons of known singleton values through the live
  per-packet `ST0601ContextProvider`; the verifier reports exactly how many
  packets and applicable field/IMAP/VMTI values received each kind of external
  assurance;
- Items 73, 95, and 97-99 have typed embedded Local Set bridges, but complete
  conformance to each referenced child standard is a separate claim from their
  ST 0601 nesting and framing;
- Item 102's ST 1010 Mode 2 structure, source-list adjacency, and matrix shape
  are verified, while the producer's statistical interpretation of the
  covariance values is not inferable from the wire value; and
- Segment/Amend hierarchy is structurally and statefully validated. The bundled
  verifier applies the selected ST 0902 MISMMS policy to the Amend root and each
  terminal Segment union; other deployment-specific MISP profiles are selected
  and enforced by the application.

These are not hidden under registry coverage: the individual rows above state
where evidence is structural, contextual, or producer-owned.
