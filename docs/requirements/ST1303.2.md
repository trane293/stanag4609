# MISB ST 1303.2 requirement trace

This trace is bound to the official 25 June 2020 Multi-Dimensional Array Pack
publication with SHA-256
`9af048d76a27c3246e5411d66c41647b6b345c56363f3b024394f7510d4a947d`.
The edition contains exactly ten active requirements and eleven requirements
that Appendix A explicitly marks deprecated.

An MDAP is a context-dependent KLV truncation pack: the invoking standard
supplies the meaning and, for Natural and RLE arrays, the element type. The
codec therefore requires an explicit `MDAPElementType` rather than guessing a
numeric interpretation from bytes.

Decoded RLE arrays remain compact. `element_at()` resolves a cell by scanning
patches in reverse order, preserving the standard's last-patch-wins behavior;
`materialize()` expands only under an explicit element limit. Decoding also
bounds pack length, dimensions, total logical elements, element width, and RLE
patch count before allocating corresponding structures.

IEEE bounds used by IMAP are quantized to their actual 32-bit or 64-bit wire
representation before element mapping. This ensures a receiver reconstructs
the same mapping and makes decode-then-encode stable at parameter boundaries.

Appendix A deprecates `ST 1303-01`, `ST 1303-04`, `ST 1303-05`,
`ST 1303-06`, `ST 1303-08`, `ST 1303-10`, `ST 1303-11`, `ST 1303-12`,
`ST 1303-13`, `ST 1303-15`, and `ST 1303-18`. They are not counted as active
requirements. Where the current normative prose retains their wire behavior,
such as BER-OID structural fields, row-major ordering, IMAPB element mapping,
and the EBytes-zero signal, that behavior remains implemented and tested.
