# MISB ST 0902.8 requirement trace

ST 0902 is a stream-level profile of ST 0601: its minimum items may be spread
across multiple packets, but every requirement must be populated at least once
in each inclusive 30-second interval. Security sub-items are decoded by the
typed ST 0102.12 Local Set codec; context-dependent marking choices remain
producer and security-official policy.

The default validator models a stream disseminated from the complete platform
and control-station system, so both Security and MIIS are required. Applications
validating an earlier stage may disable either policy explicitly. Raw packet
validation preserves malformed known field bytes by default and returns
`invalid_field` issues; callers can select strict field decoding when immediate
exceptions are preferred. Call `finish()` for finite recordings so requirements
that never appeared are included in the result.

`MISMMSValidator` also retains which of Items 75 and 104 is receiver-visible
across distributed packets. A second alternative inside the inclusive
30-second refresh window produces an `exclusive_or` issue; expiry or an
explicit ZLI clears that alternative's current state.

`MISMMSValidator.coverage()` returns the selected requirement groups as typed
`MISMMSRequirementCoverage` entries. It distinguishes current, never-populated,
and overdue values and retains each last-seen timestamp and age. Coverage is a
snapshot; issues returned by `observe()` and `finish()` preserve historical
violations even when a later observation restores the current state.
Nested Security items use explicit paths (`48/1`, `48/2`, and so on) and each
has independent population and cadence state; outer Item 48 presence is not a
substitute for any required child.
