# MISB ST 1204.3 requirement trace

This trace is bound to the acquired 27 February 2020 publication and accounts
for all 40 active requirements. It distinguishes properties the library can
prove from producer facts that software cannot infer from a received value.

## Wire formats and receiver-visible behavior

| Requirement | Implementation and evidence | State |
|---|---|---|
| ST 1204.1-01 | Binary, standalone KLV, text, and XML Core Identifier codecs; ST 0601 Item 94 integration | Verified for supported metadata paths; inserting an identifier into every imagery representation remains producer-owned |
| ST 1204.1-03, ST 1204.1-21, ST 1204.1-30, ST 1204.2-45 | `validate_miis_uuid` and version 1/4/5 generators enforce Appendix A UUID form for Sensor, Platform, Minor, and Foundational identifiers | Verified |
| ST 1204.1-04 | A typed foundational value cannot omit every component; a Sensor ID with its quality is encoded in every binary/text/XML representation | Verified when the producer supplies a Sensor ID |
| ST 1204.1-05, ST 1204.1-06, ST 1204.1-07 | Physical, Virtual, and Managed Sensor-ID-Type values map exactly to Usage Value bits | Verified structurally; the claimed quality remains producer truth |
| ST 1204.1-18, ST 1204.1-19 | `combine_miis_sensor_identifiers` applies Appendix A.1 in input order and assigns the lowest component quality | Verified against the normative Table 13 UUID vector |
| ST 1204.1-22, ST 1204.1-23, ST 1204.1-24 | Physical, Virtual, and Managed Platform-ID-Type values map exactly to Usage Value bits | Verified structurally; the claimed quality remains producer truth |
| ST 1204.1-26 | `with_miis_window_identifier` preserves the source foundational Sensor/Platform components and adds a validated Window UUID | Verified |
| ST 1204.1-28 | `MIISCoreIdentifier` rejects a Minor ID combined with any Foundational component | Verified |
| ST 1204.1-31, ST 1204.1-32 | The transported-value model rejects nil temporary Platform UUIDs, so pre-fill values cannot leave the platform through these codecs | Verified at the library boundary; temporary onboard state is outside the wire model |
| ST 1204.1-34 | `MISMMSValidator` tracks ST 0601 Item 94 recurrence and accepts the inclusive 30-second boundary while reporting later or trailing gaps | Verified for receiver-visible cadence; change events are producer inputs |
| ST 1204.1-39 | `encode_miis_core_identifier_xml` and `decode_miis_core_identifier_xml` use the required `MiisCoreId` namespace and text form, with bounded parsing and DTD/entity rejection | Verified |
| ST 1204.1-42, ST 1204.1-44 | Only RFC 4122 UUID versions 1, 4, and 5 are accepted; version 1 rejects a null MAC node | Verified |
| ST 1204.1-43 | `generate_miis_uuid5` requires an explicit namespace and non-empty device-name input | Input shape verified; uniqueness of manufacturer/model/serial facts remains producer-owned |

The unnumbered normative wire definitions are also executable: the binary
grammar and Usage Value are byte-exact against the foundational and Minor
examples; the standalone key is
`060E2B34010101010E01040503000000`; text uses four-hex-digit UUID groups and
the Appendix B dual-permutation check byte; and XML round-trips that checked
text through `http://www.nga.gov/MiisSchema/`.

## Producer and deployment obligations

These active requirements describe physical identity, provenance, lifecycle,
or behavior elsewhere in an FMV production system. The library exposes types
and strict output boundaries for them but cannot establish the real-world fact
from bytes alone.

| Requirement | Obligation and library boundary | State |
|---|---|---|
| ST 1204.1-02 | A Sensor Identifier must identify the physical generating device | Producer-owned identity truth |
| ST 1204.1-08 | Physical Sensor IDs are inserted in every uncompressed frame before storage/transmission | Producer pipeline obligation |
| ST 1204.1-09, ST 1204.1-10, ST 1204.1-11 | Physical Sensor IDs persist across power cycles, reconnects, and platform attachment | Device lifecycle obligation |
| ST 1204.1-12 | A Physical Sensor ID is not assigned to another physical sensor | Provisioning uniqueness obligation |
| ST 1204.1-13, ST 1204.1-14, ST 1204.1-15 | Replacement/removal rules govern Virtual and Managed Sensor IDs | Producer lifecycle obligation |
| ST 1204.1-16 | Virtual/Managed ID insertion follows a system-defined sensor-change tolerance, nominally one-half second | Producer event/timing obligation |
| ST 1204.1-17 | An existing Sensor ID is not replaced | Transformation policy obligation; decoded identifiers remain losslessly available to callers |
| ST 1204.1-20 | A Platform Identifier must identify the physical device or skeletal frame | Producer-owned identity truth |
| ST 1204.1-25 | Platform IDs are inserted onboard the platform | Producer topology obligation |
| ST 1204.1-27 | A conformant downstream system creates a Minor ID only when no Foundational ID arrived from the platform | Pipeline policy obligation; constructors enforce the resulting exclusive form |
| ST 1204.1-29 | Sensors and platforms generate only Foundational identifiers | Producer-role obligation; Minor and Foundational forms are distinct and mutually exclusive |
| ST 1204.1-40, ST 1204.1-41 | Manipulated imagery, metadata, and derived products retain the source Core Identifier | Application transformation obligation; codecs provide lossless decode/re-encode and the window derivation helper |

## Deprecated requirements

ST 1204.1-33, ST 1204.1-35, ST 1204.1-36, ST 1204.1-37, and
ST 1204.1-38 are explicitly deprecated in ST 1204.3. They are recorded in the
machine-readable inventory but are not presented as current conformance work.
